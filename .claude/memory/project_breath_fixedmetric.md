Built 2026-07-24 to answer: per-video SVD PC1 (`breath_svd_pc1.m`) is not comparable across videos — would z-scoring fix it? **Partly, and not the part that matters.** Z-score fixes arbitrary scale but not arbitrary sign, not basis identity, and it destroys amplitude by construction. Worse, its denominator is the whole-trace SD, so one big body movement inflates SD and silently shrinks that run's breathing — anti-comparability.

**Files** (repo root, tested on `D:\breath_tracking_test`, 21x 60 s runs @60 fps, 528x580 FFV1):
- `breath_fixedmetric_gui.m` — **the launcher**: pick ROI -> extract -> analyse, one call, the way `breath_svd_pc1.m` is used.
- `breath_fixedmetric_roi.py` — `cv2.selectROI` popup, preview overlaid with breathing-band power so you can see which compartment moves. ONE ROI per session (a per-video box is a per-video spatial weighting = the problem being solved). Writes `breath_roi.mat`.
- `breath_fixedmetric_extract.py` — all video I/O. **Run with dlc310**, see [[reference_oasis_on_this_machine]]. Registers on FULL frames first, then crops each run at its *shifted* box so the ROI follows the anatomy through the 9 px session drift. Changing the ROI auto-wipes `.breathcache`.
- `breath_fixedmetric_analyze.m` — baseline referencing + QC figures.
- `breath_fixedmetric_to_gui.m` — writes per-run `breath_pc1.mat` so `breathing_peak_gui_pc1.m` opens these traces unchanged. That GUI **detrends and z-scores** (its lines 208-209), so it is for peak/timing QC only, never amplitude.
- `breath_fixedmetric_dispaxis.m` — added 2026-07-28. 9-panel diagnostic for the DISPLACEMENT MEASUREMENT itself, which the other three figures never show: (dx,dy) cloud with the frozen axis drawn through it, on-axis vs orthogonal traces + spectra, sub-pixel magnitude histogram, per-run axis deviation and |cos| across the session. Pure re-plot of `D_all` in `breath_fixedmetric.mat` — decodes no video, runs in seconds. Takes `rootDir` as an argument.

**Two QC traps found building the dispaxis figure — both inflate apparent axis instability into a failure that is not there:**
1. **Axial wraparound.** A singular vector and its negative are the same axis, so angles must fold mod 180. Breathing here sits at ~+88 deg, right on the fold boundary, so plotting the raw folded angle makes a 2 deg wobble read as a 177 deg swing. Reported SD collapsed 67-75 deg -> 19-29 deg once the angle was expressed as a signed *deviation from the frozen axis* instead. Use `fold90(runAng - aFroz)`, never the raw angle.
2. **1-D is not the same as breathing.** A slow postural drift is perfectly 1-D and contributes a confident, wrong axis. A run only tests the frozen axis if it is 1-D (top singular value >= 0.70 of variance) AND its OWN-axis band fraction >= 0.50 — measured on the run's own axis, never the frozen one, or the test assumes its conclusion.

**The diagnostic independently recovers the death point.** On 260723 (89 runs, animal died at run ~36) it excludes 47 runs as having no breathing axis; on 260724 (256 runs over 13 h) it excludes 197, with run 1-D-ness decaying 1.0 -> ~0.5 (isotropic = no axis at all) from about hour 4-5. Where 1-D-ness is ~0.5 the frozen projection is measuring noise, and a low |cos| there is NOT evidence the axis moved — there is no true axis to compare against. Among runs that do carry breathing the frozen axis holds well: deviation +1.2 +/- 18.9 deg (260724), -15.5 +/- 29.1 deg (260723). **Sub-pixel estimation is not optional:** 99.7% of frames move < 1 px, median 0.017 px, so integer registration would return zero for essentially every frame.

**Three metrics carried side by side:** `disp` (rigid sub-pixel translation in PIXELS via `cv2.phaseCorrelate` against the run's own reference — primary), `fb` (frozen basis: one spatial mode from pooled baseline, applied unchanged everywhere), `pv` (per-video PC1, the incumbent, for benchmarking).

**Bugs found while building — all three produced clean-looking wrong answers:**
1. **Nyquist.** Cube stride 12 at 60 fps = 5 Hz sampling vs 2.67 Hz breathing → aliased to 2.33 Hz and looked perfect. Script now asserts `fps/CUBE_EVERY > 2*BAND[1]` and aborts.
2. **Pooled-mean centring of the basis.** Centring the pooled matrix on the global mean let between-run structure (illumination creep, residual misregistration) dominate the leading mode: it came out near-orthogonal to the per-run mode (|dot| = 0.32) and correlated only 0.31 with `disp`. **Centre each run on its own mean before pooling** → 0.54, and `|u1.pv1|` jumped from 0.05-0.34 to 0.75-0.99.
3. **Per-metric polarity.** Applying a waveform/skewness sign rule to each metric independently gave `fb` the opposite polarity to `disp` in all 21 runs. **Anchor every metric's sign to `disp`**, the only one with a physically defined direction.

**THE VIDEO IS CHEST, NOT SNOUT** (user corrected 2026-07-24). The grid of bright dots is reflective markers on the fur over the thorax; the textured midline strip is the sternal line. Tracheotomised, no craniotomy. So this measures **chest wall excursion**, and everything below is respiratory mechanics, not orofacial motion.

**The main scientific finding: there is no single "breathing amplitude" here — you must name the compartment.** Chest wall motion is spatially non-uniform and its *pattern* is non-stationary within a session. Over the 15 baseline runs, amplitude in the region the frozen mode weights fell to 0.68x while another region fell to 0.10x, and the hot region then recovered 2.2x from run 8 to 14. So `disp` (whole-frame) declined while `fb` (regional) rose — never contradicting, just weighting different compartments. Their **motion axes also differ by ~70 deg**: whole-frame is (+0.01, +1.00), near-vertical, while a 180x220 box on the upper-right marker cluster gives (+0.95, -0.33), near-horizontal, at 98.5% of variance. Different chest regions move in different directions and by different amounts — i.e. ribcage vs abdominal compartments behaving differently, the classic two-compartment picture, which is real physiology and NOT a nuisance to average away. **A whole-frame metric averages across compartments and is close to meaningless for amplitude.** Always set an ROI on one named compartment.

Restricting to a coherent compartment also improves every diagnostic: `u1` variance explained 45.3% -> 77.3%, `|u1.pv1|` 0.75-0.99 (dipping to 0.19) -> 0.92-0.98, and run-to-run amplitude far flatter (0.33/0.31/0.21 px whole-frame vs 1.06/1.05/1.00 px in the box, first 3 runs).

**Detect on `fb`, measure amplitude on `disp` — and never rescale a z-scored trace to a borrowed amplitude.** Measured on the 89-run 260723 session, live runs only. **All three metrics find the SAME breaths** — 119.2 / 121.0 / 120.4 per run for disp/fb/pv, and pv agrees with fb at F1 0.946 once the match tolerance is half a cycle. They differ in TIMING PRECISION, not detection: median peak-time error vs fb is ~100 ms for pv (20% of a breath cycle, 90th pct 233 ms) versus 2-3x tighter for disp; F1 at a 67 ms tolerance is 0.887 disp vs 0.493 pv; IBI CV 0.073 fb / 0.091 pv / 0.132 disp. Per-video PC1 blends chest components of differing phase and the blend shifts run to run, smearing peak times — it is fine for rate/count, poor for phase or event-triggered work. **Do not quote a tight-tolerance F1 as "detection quality"** (an earlier note here said pv had "F1 0.536, worst detector" — that was a temporal-precision number mislabelled). Narrowband SNR is likewise a poor detector ranking: fb has the lowest (1.4 vs disp 2.3) yet the steadiest timing. The tempting scheme "z-score per-video PC1, map back to a per-session average amplitude" is **bad**: `pv`'s per-breath amplitude correlates with the physical `disp` amplitude at only **r = 0.12 +/- 0.27**, so rescaling puts the right mean onto the wrong breath-to-breath variation. Rescaling fixes a scalar, not a waveform. The split is free anyway — the GUIs save event INDICES and `apply_curated` applies them to every metric, so peaks curated on `fb` yield amplitudes read off `disp` in pixels.

**Dead-animal runs are the noise floor, and they expose per-video PC1.** On 260723 the animal died at run ~36 (runs 35-36 agonal). Raw-trace band fraction separates perfectly: live 0.626-0.966, post-mortem 0.234-0.552, clean gap -> threshold 0.60 (auto-detected the boundary at run 35 without being told). Alive/dead narrowband SNR ratio: `disp` 14.7x, `fb` 8.9x, `pv` only **2.1x** — per-video PC1 still reports SNR ~1.0 on a DEAD animal because it re-fits its basis to noise and manufactures a signal. Measured floor for `disp`: 0.0069 px noise sd vs 0.115 px live, i.e. ~1% of a baseline breath. **Gotcha:** band fraction must be computed on the RAW trace; computing it on the bandpassed trace measures the filter and returns ~1.0 for everything, including dead runs (this bug silently disabled the QC).

**Baseline is NOT a stable standard in this prep.** Baseline breathing drifted 0.48x in `disp` over 75 min (rho = -0.69, p = 0.005) with rate falling 2.65 -> 2.0 Hz. Run-to-run measurement noise (successive-difference CV) is only 5-11%, so the drift is real signal, far above noise. Pooling all baseline runs into one amplitude reference would hide it — check the trend before using baseline as a denominator.

**Rig facts:** FOV drifts up to 9 px over a session (jumps when the experimenter touches the rig — gas switch at run 16), so registration is mandatory for any fixed basis; `disp` is immune since each run references itself. Mean intensity creeps +3%/75 min, so never use raw ROI mean intensity as the signal. Whole-frame chest motion is ~1.25 px peak-to-peak with ~97% of power in 0.5-8 Hz; inside a single-compartment box it is ~3x larger. Amplitude in px is only cross-animal comparable if magnification is matched — otherwise calibrate px/mm. Below ~40 px box side, phase correlation gets noisy at these amplitudes (the picker warns).
